# 微信聊天记录导出（wxexport）

把自己的微信聊天记录按会话、按月归档进Obsidian，再把新消息里的待办、承诺、决定整理成行动项笔记。默认全程不出电脑；要不要用模型、用本机的还是云端的，由你定。

## 先说清楚的几件事

- **本工具不解密任何数据。** 数据从哪来由你决定：chatlog兼容的本地接口，或者其他工具导出的JSON/CSV文件。
- **数据源工具的现状。** chatlog作者2025年10月20日收到微信官方函件后，删除了全部代码和提交历史，并建议保留旧副本的用户删除、自行评估合规风险（见[原仓库说明](https://github.com/sjzar/chatlog)）。留痕等同类项目也已下架。网上流传的分支和安装包来源不明，这类程序按设计能读到你全部聊天记录，被植入后门的后果很严重。用不用、用哪个，由你自己判断。
- **默认什么都不出电脑。** 行动项默认只生成一份提示词文件（`ai.backend: prompt`），由你自己贴给本机的工具。要自动出行动项又不让数据出电脑，用本机模型（`local`，见下）。云端Claude（`claude`）会把聊天内容发到境外，默认关闭，开之前先对照公司保密规定。
- 只用于你自己的账号和数据。

## 能做什么

| 命令 | 作用 |
| --- | --- |
| `doctor` | 检查配置、数据源、Obsidian库、API密钥和代理 |
| `list` | 列出会话（按最近消息排序），查名字和ID |
| `export` | 导出到Obsidian。默认增量，可以指定会话、时间段，或者全量重导 |
| `actions` | 提取行动项。默认只看每个会话上次处理之后的新消息 |
| `run` | 日常一键：增量导出，再提取行动项 |

有会话出错时退出码是1，放进Windows计划任务里能看出来。

## 安装（Windows）

1. 装Python 3.10或更新版本（python.org下载，安装时勾选「Add python.exe to PATH」）。
2. 在`wechat-export`文件夹里打开PowerShell：

   ```powershell
   py -m pip install -e . -i https://pypi.tuna.tsinghua.edu.cn/simple
   ```

3. 把`config.example.yaml`复制一份，改名为`config.yaml`，按注释填好Obsidian库路径和数据源。
4. 检查一遍：

   ```powershell
   py -m wxexport doctor
   ```

## 数据源

### chatlog兼容接口

接口服务开着时（默认`http://127.0.0.1:5030`），工具只读这几个接口：`/api/v1/session`、`/api/v1/contact`、`/api/v1/chatroom`、`/api/v1/chatlog`。访问本地接口不走系统代理，开着全局代理也不影响。

### 导出文件

`source.type`改成`file`，`source.path`指向文件或文件夹（会读取里面所有`.json`和`.csv`）：

- JSON：chatlog格式的消息数组，或`{"messages": [...]}`。
- CSV：默认按chatlog的表头（`Time,SenderName,Sender,TalkerName,Talker,Content`）。其他工具导出的CSV，在`source.csv_columns`里把字段对应到实际列名；没有的列写`""`。GBK编码、Excel另存过的CSV（时间写成`2026/9/3 9:05`）也能读。

几份导出时间段有重叠时会自动去重，同一份里同一秒连发的几张图、几句「好的」会保留。时间认不出来的行会跳过，并在命令行里提醒是哪个文件、跳过了几行。

### 手机上的记录

不用另做一套。先用微信自带的迁移功能把手机记录迁到电脑版：手机微信「设置」里的「聊天记录迁移与备份→迁移→迁移到电脑微信」（不同版本入口位置略有差别，手机和电脑要连同一个网络）。迁移完以后：

1. 跑一次`py -m wxexport export --full`。日常的增量导出只往后补，迁移进来的是旧消息，要全量重导才会进归档。
2. 迁移进来的旧消息要看行动项的话，用`actions --since 起始日期 --until 结束日期`单独补看。

## 日常用法

```powershell
py -m wxexport run                                    # 每天一次：增量导出+行动项
py -m wxexport list 项目                              # 找会话
py -m wxexport export --chat "项目群A"                 # 只导出一个会话（写名字的一部分也行，只要不重名）
py -m wxexport export --chat "*项目*" --since 2026-01-01   # 通配，从指定日期起
py -m wxexport export --all --full                    # 全部会话从头重导
py -m wxexport actions --days 3                       # 只看最近3天的行动项
py -m wxexport actions --chat "张总" --since 2026-09-01  # 指定会话和起点
py -m wxexport actions --prompt-only                  # 不调用API，只生成提示词文件
```

### 选会话

- 不带`--chat`就按配置里的`export.include`、`export.exclude`选；带了`--chat`只处理指定的，但`export.exclude`里的照样跳过。
- 名单和`--chat`的写法：名字或ID完全一样（不分大小写）就算；只认`*`和`?`两种通配，名字里的方括号按普通字符处理，`[内部]财务群`直接写就行。

### 导出

- 按月整页重写：`--since`、`--until`涉及到的月份会整月重新生成，重复运行结果一致。
- 新取到的某个月比归档里的条数少时（微信里删过记录、换过电脑），默认不覆盖，命令行会提示；确认要覆盖加`--force`。
- `export.since`是全局下限，任何导出都不会早于它。之后把它往前调，要用`--full`才会补上更早的记录。
- 单个会话取数或写文件出错时，记下来接着做别的会话；连续3个会话出错才停。

### 行动项

- 进度按会话记：每个会话记住处理到了哪条消息，下次只看它后面的。电脑版微信没开着时跑过一次、之后才同步进来的消息不会漏。
- `--days`、`--since`的起点晚于某个会话的进度时（中间有一段没处理过），或者指定了`--until`，都只算补看，不动日常进度，下次日常运行照样从原来的进度接着处理。
- 被拒绝或出错的会话进度不前进，下次自动重试；同一段记录连续3次失败会跳过，并在当天笔记的「未处理」里写明跳过了哪段。
- `--prompt-only`生成提示词文件也算处理过，进度会往前推。
- 只有图片、表情这类内容的会话不会送去处理。

## Obsidian里的结构

```text
微信记录/
  微信记录索引.md
  聊天/群聊/项目群A/项目群A.md              会话页：自动区+你的批注
  聊天/群聊/项目群A/项目群A（2026-09）.md    按月记录，整页自动生成
  聊天/私聊/张总/……
  行动项/2026-10-02行动项.md
  行动项/提示词/……                         --prompt-only生成的文件
```

按月记录长这样：

```markdown
## 2026-09-30（周三）

**15:40 张总**：这个格式业主确认过了吗
> 引用 李工：[文件] 投标保函格式.docx

**16:00 我**：确认过了，\$2.5M的额度
```

行动项笔记长这样（Obsidian Tasks插件能直接识别）：

```markdown
## [[微信记录/聊天/群聊/项目群A/项目群A|项目群A]]

要点：业主要求下周五前提交保函材料，格式已确认。

- [ ] 把保函材料给银行 📅 2026-09-04
    - 待办 · 责任方：我方 · 截止：下周五前（2026-09-04） · 置信度：高
    - 原话：「下周五前把保函材料给银行」[[微信记录/聊天/群聊/项目群A/项目群A（2026-09）#2026-09-01（周二）|09-01 04:30 张总]]
```

使用规则：

- 按月记录每次会整页重写，别在里面写东西。批注写在会话页「## 批注」下面，导出只刷新会话页里的自动区。
- 工具生成的链接都带库内路径，库里别处有同名笔记（比如你自己的人物笔记「张总」）也不会串。
- 会话改了备注名，目录名不变，已有链接不会断。别在Obsidian里给会话目录或会话页改名，工具是按目录找回会话的。
- 每条行动项都带原话和指向原文那一天的链接，核对规则：
  - 原话在所引消息里找不到的，标「和原文对不上，请核对」，置信度降为低；
  - 消息编号对不上原文的，不列成任务，单独放在「待核实」里；
  - 截止期原文没提的写「未明确」，不推断。
- 聊天里的`$`、`#`、`%%`、`![](…)`等符号会转义，不会被Obsidian当成公式、标签、注释或外部图片；网址原样保留。

## 行动项：选后端（`ai.backend`）

三选一，`ai.context`写一句工作背景帮模型看懂行话对三种都管用：

### prompt（默认，什么都不出电脑）

不调任何模型，只在`行动项/提示词/`下生成一份带聊天记录的提示词文件，你自己贴给本机的Claude Code / Cowork或别的工具去整理。零配置，适合先跑起来看看。

### local（本机模型，自动出，数据不出电脑）

用[Ollama](https://ollama.com)在本机跑模型，这是「自动出行动项又不出电脑」的选择：

1. 装Ollama，下载模型：`ollama pull qwen2.5:7b`（中文业务建议`qwen2.5:14b`或`32b`，机器扛得住的话）。
2. 配置里`ai.backend: local`，`ai.local_model`填你下的模型。
3. `py -m wxexport doctor`会检查模型在不在。

说实话的几点：ThinkPad这类轻薄本是集显，7b能跑但偏慢、长会话质量一般，14b以上更准但更慢；`ai.local_url`只允许本机地址，否则数据就出电脑了；会话按`ai.local_num_ctx`的长度切段，太长会被模型截断，必要时把`ai.max_chars_per_request`调小、`concurrency`设1。

### claude（云端，数据出电脑，默认关闭）

⚠ 会把聊天内容发到境外Claude。只在你确认某些会话可以外发时用，配合`ai.exclude`和`--chat`圈定范围。

- 开启：`ai.backend: claude`，或临时`actions --backend claude`。
- 密钥：`setx ANTHROPIC_API_KEY "sk-ant-..."`，重开窗口生效。模型默认`claude-opus-5-5`，`ai.effort`默认`medium`。
- 中国大陆要代理：`setx HTTPS_PROXY "http://127.0.0.1:7890"`（端口按你的代理软件；`socks5://`也行）。报「没有权限（HTTP 403）」除了查密钥，也可能是节点地区不受支持，换个节点。
- 被安全策略拦下时服务端会自动换模型重跑；仍失败的列在当天笔记「未处理」里。

装依赖慢就用清华镜像（安装命令里的`-i`参数）。

## 隐私

- `config.yaml`和进度文件`.wxexport-state.json`已在`.gitignore`里，不会提交。
- `export.exclude`：永远不导出；`ai.exclude`：导出到Obsidian，但不交给模型。
- `ai.mask`默认打开：交给模型前（local和claude都算）把手机号（含埃及、印尼号码）、身份证号、银行卡号、IBAN账号、邮箱换成占位符，会话名也一样处理。身份证、银行卡、IBAN先过校验位再遮，合同号、招标编号一般不会被误遮；带货币符号或单位的金额不会被当成手机号。
- 归档只写你本地的Obsidian库。`backend`为`prompt`或`local`时，工具不向任何外部地址发送内容；只有`claude`那一档会把（脱敏后的）聊天内容发到境外。

## 常见问题

- **提示找不到时区**：`py -m pip install tzdata`。
- **YAML报错**：Windows路径用正斜杠`D:/Obsidian/库`，或者用单引号括起来。配置文件用记事本存成ANSI也能读。
- **时间和微信里差几个小时**：归档统一按`obsidian.timezone`（默认北京时间），不跟电脑时区走。
- **提示某个月「没覆盖」**：新取到的消息比归档里少，见上面「导出」一节；确认要覆盖用`--force`。
- **想重建归档**：删掉`微信记录/.wxexport-state.json`再导出。已有目录会按会话页里的`wechat_id`认出来继续用，按月记录全部重新生成，会话页里你写的批注保留。行动项进度也会清空，下次按`ai.default_days`往回看，可能和之前的笔记有重复。
